# P2c-R Values风险后续：冻结19题的直接列值绑定审计

## 研究契约与依据

指导基点为自有仓库`bArtyom/gfm-rag` main `99e4db00837d420cba18de76175f18f910a903bf`。用户于2026-10-19再次请求继续实验。上一轮词面扫描已经停止，本轮是另行登记的一次CPU静态分析，执行其“先核对Literal与SQL列/业务编码绑定”的后续准备，不扩展旧扫描范围，不启动LLM/GPU。已读项目README、研究README、experiment-roadmap、reproducibility-contract、P2c-R成功分支和上一轮风险报告；没有新的远端指导提交。

核心假设仍是保留检索端Values、缩短Context的双视图机制。本轮只核验影响其信息保留叙事的未决问题：原19题/21个问题与evidence均不可见的常量线索，是否能绑定到**同一被移除Values的源列**？上一轮“命中Gold列”没有完成Literal到Column的绑定。

因果链：移除Values文本→常量词面消失→若参考SQL直接约束同一源列，则形成更具体的待审查线索。绑定成立只证明AST关联；业务必要性、映射效用和SQL EX仍未知。本轮属于最小消融之后的exploratory误差分析，不是新方法、第三方论文复现或独立数据库主实验。

## 固定输入、规则与分类

- 只使用已封存Full的19题优先队列、21个输入不可见Literal标记；保留原顺序。前5题Smoke通过后运行一次19题Full，Smoke与Full相同提交/源码/依赖。74道不可评题与其余可评题均不扩进本轮；不能推断总体风险率。
- 既有BIRD dev、dev_tables、P2c-R逐题/聚合、旧词面审计逐题/聚合和空白人工模板均以SHA固定。完整重放所选问题的旧词面标记，验证节点文本和选择不变。旧文本匹配与标记定义不修改。
- 使用现有SqlGlot28.0.0，SQLite解析和完整Schema名称限定；歧义列/限定失败记unknown，不猜测。Literal提取沿用旧直接谓词规则及符号、通配符、函数参数排除项。
- 在限定前给原合格Literal打AST元数据标签；限定后只追踪标签保留、值hash相同的原出现，避免从SELECT投影/别名展开产生新的数据常量。比较谓词两侧、IN列表及BETWEEN上下界只关联另一侧的直接Column，移除无语义变化的括号。
- 支持表别名、唯一可限定未加前缀列、相关子查询外层来源，以及唯一直接列投影的CTE/子查询链。函数/算术/聚合/CASE等变换、UNION、缺失/递归/歧义来源和不支持的投影均保留unknown；不求值、不运行SQL、不展开业务映射。
- 对每个按题去重的Literal标记收集其所有原出现的已解析源列ID与unknown原因。若与旧Values匹配列有交集，`binding_supported`；无交集且所有出现均解析、至少一个有效源列，`binding_mismatch`；其余`binding_unresolved`。supported可以同时有其他unknown出现，另列该数，不声称完全解析。
- 题级分类互斥：至少一个supported→supported；否则至少一个unknown→unresolved；其余mismatch。21标记必须恰好分入三类，19题也必须保持完整。mismatch只说明直接绑定不一致，不能排除其他列提供间接编码说明。

## 预算、判据与停止

一次5题Smoke、一次19题Full，0重试。各阶段最多300process CPU秒、8线程、4GiB RSS；API/模型前向/GPU/SQL执行/安装/下载均0。优先CPU；已有Qwen资源/服务检查仅为资源盘点，不是模型请求。无随机抽样/解码/训练，seed不适用。

工程成功要求所有SHA、序列、旧标记重放、分母与聚合写盘/回读通过；unknown本身不是工程失败，不允许删去。存在≥1个supported标记只决定优先审查队列价值，不是方法成功门或语义准确率。若0则说明本规则未确认直接绑定，保留unknown和间接用途边界。

任何输入/源码/重放/分母错误、资源超限或运行失败立即保留现场并停止。一次Full后无论结果如何都停止；不按观察值补充新的解析规则、模型或参数扫描。之后只整理误差证据/SQL评测设计；人工必要性判断分母仍0，未经独立语义验收不启动端到端效果主张。
