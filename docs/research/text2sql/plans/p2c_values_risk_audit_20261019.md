# P2c-R 后续：Values 信息暴露风险审计（计分前登记）

本轮依据 `3a72c13b3054951f13dfc6a7fc56422e225365c1` 的 P2c-R H1/H2 PASS 和恢复协议的成功分支。外循环结论：保留检索端 Values、缩短返回 Context 可改善节点覆盖，但是否丢失 SQL 所需的业务常量尚未验证。本轮只回答这个主线未决问题的词面证据部分；不扩展方法矩阵。

## 一个问题与假设

是否存在参考 SQL 的数据谓词常量，原本只出现在 V00 已返回列的 Values 描述中，而在 V01 实际返回的所有短文本中不可见？发现此类样本会否定“下游信息无损”的未经验证表述，决定后续人工复核优先级；词面命中不能证明语义必要性或 SQL 准确率损失。

层级为最小风险诊断（exploratory）。不重新打分、不改变任何 P2c-R 排名/装包/成功门，不生成或执行 SQL，不使用模型/API/GPU，不把 Gold 反馈进任何检索/Context 构造。

## 冻结范围与规则

- 输入保持 P2c-R Full 1534题/11库、1460列可评题及固定706题。仅审计已落盘的 V00/V01 在1024预算下的选择，其他预算不扫描。使用既有 BIRD dev `dev.json` 的参考 SQL 和原问题/已有 evidence，以及已冻结 R0/R1 节点文本。
- 原 P2c-R aggregate/private rows SHA 必须匹配登记；输入、P2b向量/行和原始query JSON SHA也要匹配。只使用现有 SqlGlot 28.0.0、现有项目环境；Smoke/Full同一提交和输入。
- AST按SQLite解析；只保留含列引用的数据谓词下的直接 Literal，路径仅允许负号、括号或Tuple包装。LIMIT/OFFSET、常量对常量谓词、空串、函数参数/计算表达式中的Literal不进入集合。LIKE/ILIKE等含`%`/`_`的模式文本排除；布尔、参数、函数语义、编码映射、同义词和模糊值不推断。
- Literal去SQL引用后作NFKC、casefold、空白归一；负号按允许包装路径的奇偶次数保留。不做模糊匹配。用词/数值边界匹配，避免`1`命中`10`或`1.5`、正数命中带负号数字；保守地要求显式正号也保持一致，不跨节点拼接匹配。规范化只是词面近似，不假设等于SQL运行时collation语义。
- 主暴露标记要求同一Literal：①命中V00已选择节点的被移除Values字段；②不命中V00这些节点的任何非Values文本；③不命中V01实际所选任何短文本。
- 分别统计Literal是否出现在原问题/已有evidence中、命中节点是否仍被V01选择、是否属于参考Gold Column。Gold Column仅说明Schema参与SQL，**不把Literal自动绑定到该Column或标成语义必需**。
- 无列Gold的74题只记SQL解析质量，不作“无暴露”结论。主暴露分母保持1460；另报告全1534解析分母、固定706、匿名库和coverage rescue/damage分层。解析失败作为未知列出，不能当零风险。

## 预算、成功判据、停止条件

固定前5题Smoke一次：输入、序列、规则与输出格式正常且5条SQL均解析成功后，允许一次1534题Full扫描。两阶段同提交，无重试。每次最多300 process CPU秒、8线程、4GiB RSS，模型/GPU/API/SQL执行均为0。

工程成功要求哈希/分母/持久化校验通过；Full解析覆盖至少95%，失败样本单列。若暴露数>0，结论仅为“存在待审查的Values词面信息移除线索”，V01仍是离线候选；若为0，也只表示冻结规则未发现线索。两种结果均在一次Full后停止，不搜索更多匹配规则。

这不是语义安全门：人工复核=0、语义必要性分母=0，不能据此开始全局去Values或宣称SQL EX改善。完成后进入人工Values必要性复核/固定Generator与数据库留出方案设计，不自动启动新的LLM/GPU实验。
