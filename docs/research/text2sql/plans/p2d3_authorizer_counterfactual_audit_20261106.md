# P2d.3 authorizer 拒绝候选的只读反事实审计

**状态：预注册的探索性错误归因；不是新的 SQL 修复方法，也不追加模型生成。** 审计只重放 P2d.3 已封存的输出，回答受限 authorizer 是否拒绝了本来可执行且正确的 SQL。

## 研究问题与依据

P2d.3 的 A2（只提供 V00 检索上下文并阻止读取上下文外表列）Set EX 为 17/66，A0 无修复为 18/66。Full 中发生 6 个初始 SQL 上下文拒绝，另有 8 个 A2 修复候选因上下文外字段被拒。现有聚合不能区分：安全门拦截了正确答案，还是只拦截了错误候选。

**问题：** 在保持原 SQL 文本、BIRD 数据库和评测规则不变时，6 个初始 SQL 与 8 个被拒修复候选中，有多少能在完整数据库 schema 下通过同一只读检查、执行并匹配参考查询结果？

- 若有被拒修复候选达到 Set EX，说明本样本中 authorizer 会拦截数据库层面正确但上下文外的候选；这不等于移除 authorizer 后的整套系统会得到同样收益。
- 若没有被拒修复候选正确，则本次 A2 准确率下降不能归因于这 8 个候选拒绝。6 个初始拒绝另与同题 A0 的冻结结果逐题对照。
- 审计结果只解释本轮封存输出的候选层面；不估计新策略的模型生成行为或总体准确率。

## 方法与固定范围

- **数据：** 复用 P2d.3 `full_003` 的 66 题及其 `prepare_002` 冻结输入。只分析 A2 初始上下文拒绝和 A2 被 authorizer 拒绝的修复候选；样本条件由已保存的 authorizer 状态决定，不按正确性挑选。
- **输入：** 初始 SQL 取自与 A2 共用同一次生成的 A0 封存输出；8 个拒绝修复候选取自同题 A2 的已保存本地响应。Gold/reference SQL 只在全部输出封存后用于执行比较。
- **回放：** 对这 14 个候选使用 P2d.3 相同的 SQLGlot 只读校验、SQLite immutable/query-only 执行器、超时、行数、结果字节和 SQLite heap 限制；只移除“必须来自 V00 上下文”的 allowlist。不得修改或修补 SQL。
- **主指标：** 8 个修复候选中，参考查询可执行的样本数，以及其中完整 schema 下只读可执行且 Set EX 正确的数量；参考不可执行的案例保留为不可比较，不记作 SQL 错误。另报告可解析、可编译和候选可执行数量。
- **初始 SQL 对照：** 对 6 个初始拒绝案例，报告同题 A0 与冻结 A2 最终 Set/Bag 正确数、A0 正确而 A2 错误的配对数；重放初始 SQL须与已存 A0 结果一致，否则审计停止。
- **Smoke：** 固定选取一个初始拒绝和最多两个被拒修复候选，只检查输入完整性与安全回放路径；不计入 Full 的 6/8 统计。

## 实验层级、预算与停止规则

- **层级：** P2d.3 的探索性错误分析，CPU-only；不是新的主实验、消融或独立复现，不升级任何方法主张。
- **核心假设：** 作者化边界可能拦截在完整 schema 下正确的查询；对立解释是被拒候选本身错误或不可执行。
- **预算：** 最多 6 条初始 SQL 与 8 条修复候选，共 14 条只读 SQL 回放；最多 300 秒 wall、300 秒 CPU、4 GiB RSS；最多 8 个 CPU 线程。GPU、模型、外部 API、依赖安装和下载均为 0。
- **成功判据：** 所有来源 seal、预测 hash、数据库 hash 和源码 commit 均匹配；Smoke 覆盖两种候选类型；Full 完成 6/6 初始 SQL与8/8修复候选的分类。成功只指审计完整，不是方法有效。
- **停止条件：** 任一 seal/hash、数据库、分支或源码不匹配；响应缺失/不完整；只读门拒绝规则失效；评测输入缺失或受损；资源预算超限。冻结评测器判定 Gold/reference 不可执行时，将该例标为不可比较并保留分母说明，不将其计为 SQL 错误。停止后不补生成、不换样本、不更改 SQL。
- **报告边界：** 公开匿名计数、运行配置和 hash；不公开问题、SQL、数据库名、逐题结果、响应或本地绝对路径。
