# P0 FK mapping pair-level 双人盲审材料准备方案

**状态：独立材料准备方案；尚未执行、未生成新材料、未联系人类审阅者。** 实验 ID：`p0_fk_mapping_pair_level_blind_review_20261106_01`。这不是模型方法 Pilot 的正式注册；模型 Pilot 仍需后续满足双人标签门。

## 为什么需要新版本

原盲审包包含 49 道问题、51 个问题×表对；匿名结构盘点发现其中只有 8 对含至少两个不同有效 FK mapping。包的抽样目标是检查 FK 定义分歧，并非映射级排序，因此无法满足原 G-reasoner Pilot 的可区分映射分母。

冻结容量审计在可解析的 1,127 个 BIRD dev `JOIN ON` 问题中找到 176 个含至少两个不同有效 mapping 的问题×表对，覆盖 4 个数据库。去掉任意 5 个已解析问题后，已观察到的候选下界仍有 170 个多映射对、4 个数据库。13 个问题的参考 JOIN 表对无法由当前解析器完整抽出；新包只使用可解析、身份稳定的候选，不把这 13 个问题当作负例或零候选标签。

旧盲审包与 A/B 回复文件均保持原样。新包使用独立 run ID、seed、文件名和本地私有目录；不合并、覆盖或读取旧 A/B 回复内容。

## 研究问题与范围

此材料准备只服务于同一个后续问题：**在参考 JOIN 派生的固定表对及其已声明 FK 候选下，两位独立审阅者是否能给出足够一致、可区分的映射接受集合，从而评价冻结 G-reasoner 的 Accepted@1？**

表对来自参考 SQL 的 `JOIN ON`，所以这是“表对已知时的 FK 映射排序”条件式任务。它不测端到端表检索、缺失 FK 推断、无 FK 合法 JOIN、SQL 执行或跨库泛化；也不能宣称评测过程完全 Gold-free。

## 候选与抽样协议

- 冻结沿用容量审计中已校验的 5 份数据输入 hash、SQLite 有效 FK artifact、canonical mapping identity 和 SQLGlot 表对解析规则。
- 样本单位为问题×表对。仅保留同一数据库、同一无序端点表对具有至少两个**不同、完整、有效且身份稳定** FK mapping 的单位；复合 FK 作为完整有序列对整体呈现。完全重复声明合并为一个 mapping，重数不作为新候选。
- 每个问题最多抽一个多映射表对，避免同题重复贡献多个主指标样本。若同一问题包含多个符合条件的表对，按预注册 seed 与稳定哈希选一个，不查看人工标签或模型分数后挑选。
- 目标准备 60 个问题×表对，使用固定 seed `20261106`。在匿名数据库层做确定性平衡抽样，优先覆盖容量审计识别出的 4 个候选数据库；每库目标 15 个，某库可用数不足时按稳定哈希顺序把空缺分配给其他库。若唯一问题数不足 60，或最终候选池不能覆盖至少 3 个数据库，则停止，不降低数量要求、不换 seed、不从旧包补样。
- 该 60 个单位只决定送审材料规模，不表示 60 个都能成为 Pilot 分母。两位审阅者须先独立完成全部 A/B 表单，之后才统计共识与可裁定数。

## 盲审呈现与标签规则

每个审阅单位向 A、B 展示自然语言问题、表对名称和该表对全部有效 FK mapping 的完整有序列对。两份包分别随机打乱案例和候选次序；相同 mapping 在 A/B 两份中的匿名 ID 稳定对应。不得展示数据库 ID、题目 ID、Gold SQL、`ON` 表达式、候选来源、模型分数、排名或旧分层信息。审阅者需要看到表名和列名来判断业务角色；因此材料是方法来源盲，而不是 schema-name 盲。

审阅者从 `single_mapping`、`multiple_mappings`、`cannot_determine`、`no_declared_fk`、`other` 中选择，并标出接受映射集合、置信度 1–3 和理由类别。只有两人决定完全一致、接受集合完全一致且双方置信度至少为 2，才计为共识。模型不得代标或裁决分歧。

## 材料准备门、停止条件与后续 Pilot 门

材料准备成功须满足：输入 hash 全部匹配；候选身份与完整有序 FK 列对一一对应；A/B 案例集、候选集合和 ID 对应完全一致；去重后 60 个问题×表对、至少 3 个数据库；隐私扫描通过；所有文件权限符合本地私有要求。

取得两份真实人工回复后，模型 Pilot 仍须单独检查既有冻结门：排除 5 个问题级 Smoke 后至少 30 个可裁定问题×表对，其中至少 20 个为结构可区分映射对，并覆盖至少 3 个数据库。主分母还须有非空接受集合且至少一个候选被拒绝。未通过即止于标签分析，不加样、不降阈值、不运行模型。

满足模型数据门后才能另行登记 Smoke/Full 配置。主方法比较固定为 reified G-reasoner 对 Dense cosine；BM25 和不看 Query 的结构排序只作次级对照。成功门沿用原方案：Accepted@1 至少高 5pp、净救回至少 4 个可区分对，且至少 2 个各自拥有不少于 5 个可区分样本的数据库配对净救回为正。未过则停止本 BIRD dev 映射排序方向。

材料准备阶段 CPU-only；不调用 GPU、模型、API，不执行 SQLite，不训练或安装依赖。问题文本、SQL、映射清单、A/B 包、回复与逐题 manifest 全部留在本地。公开报告仅保存匿名计数、哈希、配置、脚本和偏差说明。
