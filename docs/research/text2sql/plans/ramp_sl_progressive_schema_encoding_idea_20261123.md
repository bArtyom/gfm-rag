# RAMP-SL：面向完整召回的渐进式 Schema 编码

> **状态：已获用户授权进入首轮最小可行性实验。** 本文整理自用户提供的 GRAST-SQL 路线图与代码审计建议，并结合当前研究仓库中已有结果作了概念审阅。当前只执行独立预注册的“编码预算上限 gate”；候选方法尚未验证，也不代表完整 GRAST-SQL 复现。
>
> 来源版本：用户附件日期 2026-11-22；本次整理日期 2026-11-23。附件中的源码审计基于可变 `main`，没有记录可复核的 commit；本次未运行 GRAST-SQL，也未重做整仓代码审计。

## 一句话解释

GRAST-SQL 先用问题相关性筛出一批字段，再对候选字段做较昂贵的问题感知编码，最后用图模型重排并补齐连接字段。RAMP-SL 想问：**当昂贵编码预算有限时，下一批应该编码哪些字段，才能提高整道问题所需字段的完整保留率？**

直观例子：问题要找“未完成付款的订单金额”。`order_status`、`payment_status`、`shipping_status` 可能词面都很相关；如果只有少量字段能读取完整描述和值样例，计算应优先花在能区分这些候选的字段上，而不是机械地沿初始粗排名继续取列。

## 问题、洞察与机制

**问题。** 附件报告称，GRAST-SQL 某些启用粗检索的运行路径会先把全库裁成 Top-M 子图，随后编码、图重排和连接补齐都只看该子图。因此初筛漏掉的字段无法被后续阶段找回。这个现象来自附件对特定代码分支的审计；由于审计没有固定 commit，本次将它作为待复核的动机，不当作对当前 `main` 的独立确认。

**洞察。** “花多少计算给字段做问题感知编码”和“最终给 SQL 模型输出多少 Schema”是两个不同预算。某字段值得高成本编码，不表示它最终一定要输出；某字段也可能仅凭便宜信号就足以进入最终 Schema。若二者混成同一个 Top-K，方法无法表达这种差别。

**机制。** 保留全库字段的低成本表示和稳定 ID，只对当前看起来最可能改变整题字段集合判断的候选做高成本编码。用状态相关的效用分数选择下一批字段：

\[
u(c\mid q,X)\approx\frac{\text{编码字段 }c\text{ 后整题集合损失的预期下降}}{\text{该编码的实际成本}}.
\]

编码后更新图状态与候选分数，再做最终集合选择和连接闭包。首版应固定为两轮，以隔离“按需分配编码”本身；不把主动编码、集合损失、全局注意力、摘要图和 Steiner 改造一次性捆成一个贡献。

### 三种预算必须分开

| 符号 | 含义 | 必须如何计量 |
|---|---|---|
| **M** | 高成本问题—字段编码预算 | 实际编码输入 Token、列数、批次数、墙钟延迟；列数不能代替真实成本 |
| **K** | 最终选出的字段数量或策略上限 | 与编码过哪些字段分开报告 |
| **B** | 连接闭包和 Schema 序列化后的输出 Token 预算 | 所有基线都用同一输出格式和闭包规则 |

## 概念判断

### 值得保留的部分

1. **问题具体且贴近 GRAST-SQL 的目标。** 它试图同时控制筛选完整性和昂贵编码成本，研究对象是大型 Schema 下的检索前端。
2. **关键区分清楚。** M、K、B 分离后，可以检验“多做编码”与“多输出字段”分别带来什么。
3. **不依赖少数复杂 JOIN。** 单表宽 Schema 中的同类字段歧义也可能产生类似的编码预算问题。

### 主要顾虑

**C1｜创新边界目前过宽。** GRAST-SL 官方 README 将 V2 的粗向量检索、全局列注意力列为路线；这并不等于 RAMP 已被实现，但说明“加粗筛/加全局注意力”不能算新增贡献。KaSLA 已研究受预算约束的 Schema 集合选择；AttnLink 已使用集合级正例目标与覆盖下限；EviLink 已按不确定性获取更细粒度的字段证据；AEGT 已研究自适应截断和外键扩展。RAMP 可能保留的差别是：**有限预算用于选择哪些列执行昂贵的问题感知编码，并估计其对全题字段集合的边际收益。**这条差别需要更完整的相关工作检索和直接比较，不能仅靠新名称成立。

**C2｜与本仓库近期方向有明显邻近。** 本仓库的预算内修复监督试验已经研究：在固定连接闭包与 Schema Token 预算下，如何通过可行修复信号保住字段绑定。该试验报告为 independent/global/repair/whole-dense = 52/50/64/79（100 题），总体 gate 未通过；版本已停止。它与 RAMP 的核心对象不同：前者监督最终字段集合在输出预算内如何修复，后者要决定哪些字段获得昂贵的查询条件编码。但二者共享“预算内保护完整字段集合”的上位问题。RAMP 不能作为该失败版本的直接续跑或改名；需要证明新变量确实是 **编码预算 M**，而不是再次调整输出集合预算 B。

**C3｜机制可能变成一组模块的拼装。** 全库低成本池、未编码区域摘要、混合精度 GNN、集合损失、效用头、两轮调度和连接闭包都在草案中。若同时加入，难以判断收益来自哪项。更简洁的核心是“保留低成本候选视图 + 按整题集合收益分配高成本编码”；区域摘要和全局注意力替换应先作为可选组件。

**C4｜效用估计不能偷用测试时的昂贵结果。** 训练中可以用训练标签和离线高成本表示构造升级前后的监督，但实际推理只能访问已编码字段的高成本表示。训练缓存的时间、空间和模型调用成本要单列。批次中多个字段的收益可能重复，不能把单列效用直接相加并声称最优。

## 与最近工作的区别

| 工作 | 已有机制 | 对 RAMP-SL 的影响 |
|---|---|---|
| [GRAST-SQL 原论文](https://arxiv.org/abs/2512.16083) | 问题感知字段相关性、FD 图重排、Steiner 连接补齐 | RAMP 应插入其编码预算分配环节，不能把原有图或 Steiner 再命名为新方法 |
| [GRAST-SL 官方 README](https://github.com/thanhdath/grast-sql) | V2 计划含粗向量检索、全局注意力、增强 Steiner 与统一小模型；README 标为 Coming | 这是作者路线规划，不是已发表结果。RAMP 需区别于固定 Top-M 后统一精排的实现目标 |
| [KaSLA（ICDE 2026）](https://ieeexplore.ieee.org/abstract/document/11629376) | 用 Knapsack 在受限 Schema 输出预算下平衡相关性与冗余 | 输出集合预算与编码计算预算不同；RAMP 必须比较并明确只主张后者 |
| [AttnLink](https://arxiv.org/abs/2608.00693) | 由模型注意力打分，并用 set-mass 与 adaptive floor 促进多个必要字段被覆盖 | “集合完整性损失”本身不新；RAMP 的候选差异只能落在高成本编码的动态分配上 |
| [EviLink](https://arxiv.org/abs/2605.29670) | 多条 SQL 假设下按不确定性选择字段证据，并可按层级补充统计证据 | 与“只在不确定字段上继续花计算”概念接近；RAMP 要区分模型编码计算与 agent 获取数据库证据 |
| [AEGT / ElbowHop](https://arxiv.org/abs/2611.20979) | 每题自适应阈值并沿外键图找回桥接表 | 动态阈值和 FK 扩展应作为强基线，不能单独作为创新 |
| 本仓库 [预算内修复监督报告](../reports/budget_repair_attention_bird_20261121_01/README.md) | 在固定闭包和输出 Token 预算中学习修复字段集合 | 是本项目内部最近邻；保留 RAMP 时必须单独定义并控制编码成本 M |

本轮做了针对性来源核查，不是穷尽式 novelty review。文中只把官方论文、正式会议/出版页及作者仓库支持的机制列为已核对内容；附件列出的其余相关工作仍需逐项检查后，才能支持更强的新颖性结论。

## 建议保留的窄化版本

> **研究问题：** 在固定高成本问题—字段编码 Token 预算 M、固定最终 Schema Token 预算 B 下，是否能从完整低成本候选视图中选择性执行高成本编码，使整题必要字段完整保留率优于固定 Top-M、简单不确定性策略和已有自适应证据获取方法？

这一定义把贡献压到“编码计算如何分配”。若实现只是在更多字段上调用同一模型、允许更大的最终 Schema，或只改注意力层，就没有验证该主张。

后续若另行决定进入实验设计，最低限度需要区分：固定 Top-M、同成本更大/分批粗排名、熵或分歧优先、以及效用驱动的渐进编码；同时固定 B，报告 FullColumnRecall、字段 Precision、真实编码 Token 和端到端延迟。若用参考 SQL 字段集合评估，应明确多种合法 SQL 对标签完整性的影响，并使用数据库隔离的验证范围。此段是候选证据思路，不是已冻结实验协议。

## 与另两个候选方向的关系

- **CAB-SL（闭包感知预算化集合选择）**直接优化连接补齐后的最终输出成本。它实现较直接，但与 KaSLA、AttnLink 的预算集合选择更近，暂不作为主方向。
- **PLGF-SL（关系来源感知的局部—全局融合）**针对真实外键与推断边的可信度差异。只有先证明预测边噪声是实际瓶颈，才值得单独开发。

三者先不合并。RAMP-SL 是当前唯一保留的候选；这不等于通过项目主线 gate。

| 概念洞察 | 3 | 分离 M/K/B 有用，但主动分配昂贵计算并不是新的一般思想 |
| 机制逻辑 | 3 | 保留低成本候选、按集合级边际收益升级在逻辑上可行；效用标签、低/高精度分数校准和批间冗余仍需定义 |
| 简洁性 | 2 | 原方案一次引入多组模块；保留候选池和动态编码器调度即可作为最小核心 |
