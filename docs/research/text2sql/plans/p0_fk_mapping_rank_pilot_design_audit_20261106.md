# FK 映射排序 Pilot：设计审计与近期文献更新

**状态：实验设计审计；不是新实验注册，也未运行模型。** 本文补强 2026-11-05 的候选方案，原候选文件保留不改。只有两位真实审阅者提交独立标注并通过数据门后，才可另行冻结最终执行注册。

## 决策摘要

下一项仍保留为一次有界的 **冻结 G-reasoner FK 映射排序迁移/证伪 Pilot**。当前不新增通用 SQL 修复、schema packing、图扩展或 synthetic sensitivity 实验：P2d.3 没有显示受限修复收益；近期工作已覆盖静态约束修复、执行反馈、预算搜索、相干表检索和数据库上下文压缩；G0/G2 的主要未决点是模型能否在真实、可审阅的映射候选间排对，而不是能否产生不同分数。

本 Pilot 只回答一个条件问题：**给定问题、参考 JOIN 推出的表对，以及该表对已有的 FK 映射候选，预训练 G-reasoner 能否比冻结 Dense Cosine 更常把两位审阅者接受的映射排在第一？** 它不检验端到端 JOIN 发现、缺失 FK 推断、SQL EX 或跨库泛化，也不作为新算法新颖性声明。

## 证据与当前痛点

- G0-02 在 4 个合成映射问题上为 G-reasoner 2/4、Dense Cosine 4/4；该 checkpoint 尚未显示映射排序优势。
- G2 说明关系输入干预能改变非对称合成图的节点分数；各条件 top-1 均未改变，因此关系敏感性尚未转化为关系判别能力证据。
- BIRD FK 结构、候选定义和 mapping identity 已经审计；这只能给出结构候选，不能替代业务角色金标。双人盲审包含 49 道题、51 个问题×表对，覆盖 6 个数据库；目前可信双人 Role 标签仍为 0。
- P2d.2 的 28 条失败中，13 条属于限定符/作用域问题，4 条引用不存在标识符，1 条误用可见字段；但 P2d.3 A2 的 Set EX 为 17/66，低于 A0 的 18/66。继续做通用 SQL 修复不能直接回答当前 QuadGraph 方法问题。
- P2c-R 的 +10.96 pp 是固定预算下离线 Schema 完整覆盖收益，P2d 的 30 题确认正确数为 8/7/8；两者都没有形成 SQL 执行提升证据。

## 近期文献如何改变实验优先级

1. **通用 SQL 修复已很拥挤。** 2026-10-30 提交的 Post-SQLFix 将修复组织为分层静态检查、Schema 感知诊断、接受前验证和有限重试。P2d.3 的 authorizer 安全门与此类工作邻近，所以不再用“加一次错误反馈修复”作为新方向。见 [Post-SQLFix（arXiv）](https://arxiv.org/abs/2610.41472)。
2. **相干表检索和表兼容性已被直接研究。** CORE-T 通过表用途元数据与兼容性缓存，在初次检索后选择结构相容的表集合；一般性的“Dense 召回后再保证 joinable table set”不作为新方向。见 [CORE-T（EMNLP 2026）](https://aclanthology.org/2026.emnlp-main.89/)；join-graph 遍历及边评分已有 JoinGR 覆盖，详见[既有文献更新](p0_fk_mapping_rank_literature_update_20261106.md)。
3. **一般 Schema 压缩不再优先。** DBCC 从数据库侧压缩重复结构和冗长文档；P2c-R 的短 context 结果应保留为本地工程证据，不扩展成通用压缩新方法。见 [DBCC（arXiv）](https://arxiv.org/abs/2606.28601)。
4. **增加搜索预算也不是空白。** BASS 用结构化 SQL 单元、执行门控评分和停滞感知预算控制来分配候选生成计算；当前不追加多候选采样或更长修复循环。见 [BASS（Findings of EMNLP 2026）](https://aclanthology.org/2026.findings-emnlp.1025/)。
5. **交互式证据获取与现有静态任务设置不同。** PASCAL 研究从知识源和用户处按成本获取缺失证据；当前盲审数据及 BIRD dev 路线不含此类交互轨迹，不能直接复用其结论。见 [PASCAL（EMNLP 2026）](https://aclanthology.org/2026.emnlp-main.465/)。

这些工作共同支持把后续实验收窄到现有 G-reasoner checkpoint 的真实标签迁移检验；它们不构成“本 Pilot 具有算法新颖性”的依据。

## 设计修订

以下条款是原候选方案进入正式注册前必须采用的设计修订。除这些明确改动外，原始候选集、数据来源和研究范围保持其各自历史记录。

### 1. 固定主比较，避免事后挑最强基线

- **唯一主比较：** Reified G-reasoner 对 Dense Cosine。Dense 是预先指定的主基线，理由是 G0-02 中 Dense 4/4、G-reasoner 2/4，且它使用相同文本候选，不需要训练。
- **次级控制：** BM25 和不看问题的结构排序都报告，但不在同一 Full 集上挑选最高分基线后再将它命名为主对照。
- 所有方法使用相同的问题、候选 mapping 集合、文本字段、复合键完整映射和稳定 ID；G-reasoner 沿用同一官方 checkpoint，不训练、不微调、不改关系传播。

### 2. 冻结可裁定分母

审阅决策与候选 mapping 集合必须满足原双人共识规则：两位审阅者的决定和映射集合完全一致，且两人置信度均至少为 2。主指标 `Accepted@1` 只计入同时满足以下条件的“可区分映射对”：

- 至少有 2 个不同、结构有效且 identity 已冻结的候选 mapping；
- 共识接受集合非空；
- 至少有 1 个候选不在共识接受集合内。

候选只有一个、审阅者接受全部候选、无法裁定、没有声明 FK 或映射身份无法对应的案例，仍分别报告数量和覆盖情况，但不进入主排序准确率分母。复合 FK 按完整有序列对评分；重复的相同 FK 声明按唯一 mapping identity 处理，重数只作元数据。

### 3. Smoke 与 Full 数据不重叠，并设置运行后的样本门

- 先按固定 seed、稳定 question key hash 从已达共识的候选中确定 5 个 **问题级** Smoke 单元；只按冻结标签门筛选资格，不参考任何模型分数。Smoke 只验证特征、图、分数和输出结构；不计入正式指标。若同一道问题含多个表对，Full 中排除该问题的全部表对。
- 只有在排除 Smoke 问题后，Full 仍有至少 30 个可裁定问题×表对、其中至少 20 个为上述可区分映射对，并覆盖至少 3 个数据库时，才启动 Full。
- 不满足门槛时止于人工标签报告；不追加题目、不换抽样种子，也不放松一致性条件。

### 4. 指标、聚合和成功门

- **主指标：** 可区分映射对上的 `Accepted@1`，即排名第一的 mapping 是否属于共识接受集合。
- **辅助指标：** `Accepted@3`、首次接受映射的 MRR、可裁定覆盖率、不可判定与 no-FK 覆盖情况、配对救回/损坏计数。
- 同一问题可能有多个“问题×表对”，因此统计不确定性以问题为重采样簇；只有 6 个候选数据库时，数据库级结果和 leave-one-database-out 仅作描述，不给出确认性显著性结论。
- 保留原方案的筛选要求：G-reasoner 相对 Dense `Accepted@1` 至少提高 5 个百分点，且至少净救回 4 个可区分问题×表对（GFM-only 正确减去 Dense-only 正确）；至少 2 个各自拥有 ≥5 个可区分样本的数据库，其库内配对净救回数都须为正。此门是小样本筛选规则，不是有统计功效的确认性检验；所有逐库方向均须报告。
- 即使通过，也只升级为独立数据库复现候选；未通过则停止在本 BIRD dev 映射排序方向继续调关系文本、prompt、阈值或拓扑。
