## 2. 关键实测指标

| d | Table R@10 | Column R@5 | Column R@10 | Column R@20 | Column MRR | Column MAP | 完整表列@2048 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 512 | 99.88% | 51.53% | 67.31% | 78.80% | 81.12% | 53.80% | 78.90% |
| 1024 | 99.93% | 52.93% | 68.06% | 79.16% | 82.78% | 55.28% | 79.59% |

以上是**逐题宏平均**。1024 的 Column R@10 有 **4,107 / 6,523 个 Gold 列元素命中**，元素微平均约 **62.96%**，和逐题宏平均 **68.06%** 不是同一聚合口径，不得混用。

512→1024 的配对：Column@10 有 **154 题改善、117 题变差、1,189 题相同**；完整表列@2048 有 **18 题恢复、8 题损坏、1,434 题不变**。本次数字与历史 P1 的配对不能未经对齐直接相减；由于下述复现差异，历史门槛仍按 P1 原协议判定全体低维 NO-GO。

1024 的 Gold 列排名 **p50=6、p90≈51.8、max=198**；Gold 列 Top-10 中 2,416/6,523 没被召回。这是下一轮 Column Scoring 的首要目标，不能由 Table@10 接近满分就认为 Schema Linking 解决。

### 预算–质量权衡（1024，逐题平均）

| Budget | Gold 表列元素 Recall | Precision | 完整表列问题率 | 平均返回节点 | Gold 元素/1000 tokens |
|---:|---:|---:|---:|---:|---:|
| 512 | 70.49% | 25.89% | 35.48% | 17.02 | 8.43 |
| 1024 | 82.40% | 18.21% | 56.44% | 30.35 | 5.38 |
| 2048 | 92.09% | 13.21% | 79.59% | 54.73 | 3.41 |

2038 不是优化目标：预算越大，覆盖自然升高，但候选噪声和 token 成本同步增长。应当固定 512/1024/2048 三档预算，优先比较 512/1024 的检索精度和完整覆盖、以及相同预算下的 Pareto 改进。

### 指标饱和性是实验设计风险

- **10/11 库表候选数≤10；1,360/1,534 题（88.66%）的 Table@10 是候选数决定的平凡满召回**。在大表库的 Table@5 或按候选数归一化比较前，不可宣称表链接语义已解决。
- **6/11 库完整 Schema≤2048 tokens，对应 754/1460 题（51.64%）**；2048-token 的完整率包含大量几乎不需要排名的库。剩余 5 库 **706 题** 为 2048 budget 非饱和子集，应当独立作为主要诊断视角，**仍报告全部 1460 题**。
- 1024/2048 预算下全部 1,460 题的 Gold-only 节点文本均可以装入（Oracle Fit 100%）；因此当前缺失更多是排序、候选分配、贪心装包、词面/语义匹配问题，并非 Gold 本身过长导致必然放不进。
- 注：贪心检索不会感知 Gold；Gold-only Fit 是评测理论上界而不是可用在线策略。

### 潜在失败信号，不要当成因果结论

对 Gold 列元素的**非互斥文本特征**：Query 与列/表名称有 token overlap 的比例，在命中列中为 56.46%，未命中列中为 33.32%；有 values 描述的比例在命中为 32.19%，未命中为 14.69%。这支持对 BM25/词法和字段描述作用开展消融，但**不能证明词法重叠或 values 导致命中**。不能将金标列特征用于在线评分的特权输入。

## 3. 两个不同且独立的 NO-GO

### A. 历史逐题复现 FAIL（当前阻碍 P2a）

- 检查 14,896 项，匹配 14,805 项，**91 项不符，99.389% 一致**，多数是 Column R@5/R@10 hit 数。
- 原始 P1 没保存用于重算的有序向量/排名缓存，也缺准确序列化规则；**不能确定唯一原因**。可能是节点顺序、浮点误差/并列分数排序，或未归档的历史流程差异。
- 新旧全量均分很接近**不代表逐题严格相同**；本轮原预注册 Gate 为全项相同，故严格标记 FAIL，不允许事后修改老 Gate 成 PASS。
- 但 P1.5 自身有可信的哈希/完整日志与统计：**建议采取独立的“新基线冻结协议”**，允许在限定的差异审计后以当前代码和输入进行同一次实验内的 S0/S1/S2 配对比较，不把历史 P1 当严格相同的 baseline。这是**新的预注册实验**，不是重写 P1.5 的失败结论。

### B. FK/Join-Instance Gate FAIL（独立阻碍 Role/Path）

- 11 库 SQLite 外键约束原始实例 103，100 有效、3 无效；BIRD JSON FK pair 102，存在 **5 个仅 JSON 侧、2 个仅 SQLite 侧**的有效匹配差异。
- 1,534 题中有 1,140 题含显式 JOIN ON，合计 1,428 个 ON 条件：**1,199 唯一匹配 SQLite FK，204 未匹配，25 歧义**。
- 只有 **932/1140（81.75%）** 的显式 JOIN 题所有 ON 条件都唯一匹配；另有 **197 题**存在同表对多 FK 候选。
- **不可把“未匹配的 ON 条件”直接归因为 SQL 错误或漏 FK：SQL 可以合法地使用非声明式 JOIN**。也不可从这一轮数据自动断言 197 题的真实业务角色可唯一判断。
- 在建立严格、无泄漏的 Join-Instance 映射、多路径 Gold/人工歧义标签前，不做 Role/Path Accuracy、可训练 Edge Gate 或 SQL Path Loss。

## 5. 必须保留的结论边界

1. P1 历史 128–1024 维 NO-GO 没有改写，512 的向量存储节省不等于端到端成本减少。
2. P1.5 严格历史复现仍 FAIL；**不以新实验流程豁免/追认原 Gate**。
3. 新 baselines 只支持“同一次冻结输入下各 scorer 的配对差异”；不直接宣称相对旧 P1 逐题改善。
4. BIRD dev 已反复用于方案制定，当前探索结果不能当独立跨数据库泛化证据。
5. 当前没有 GraphReasoner GNN、Jev、SQL EX 新结果；不能把表/列召回等同于 JOIN 或 SQL 正确。
